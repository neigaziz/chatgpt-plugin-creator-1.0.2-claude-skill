# Public directory preparation (opt-in)

Workspace upload is not public publication. Read current submission snapshot/errors before each release; portal behavior may change. Run the creator's public profile only for explicit public preparation.

## Metadata and assets
Actual publisher author.name and developerName; listing displayName/shortDescription <=30, longDescription <=4000, category from supported list, logo and composerIcon recommended. Primary logo required before submission. Use actual accessible HTTPS product/support/privacy/terms URLs for remote MCP; homepage does not fill listing URLs. No fabricated legal documents, domains, verified identities, support claims, demo recordings or screenshots. Up to 3 unique one-line <=128-character starter prompts, no @mentions. Confirm brand contrast and image dimensions manually (offline tool checks file presence/type/size only).

## Components and tools
At least one valid skill for this conservative public web profile. One connected remote MCP per plugin; declarations for multiple servers do not mean all can be connected. No .app.json/app references or lifecycle hooks for current public ZIP submission. Desktop-only/local MCP is a separate program and out of scope.

## Initial MCP review
Prepare exactly five positive test cases and three negative cases; positive cases need description, prompt, expected tool names and observable expected behavior. Negative cases must explain safe non-action/clarification. Provide an accessible real demo recording. Run cases with a dedicated sample-data account; report execution evidence separately. Add actual release notes. Keep sign-in credentials, reviewer instructions, MFA arrangements and challenge tokens OUTSIDE package; enter permitted reviewer details in secure portal form only.

## External gates (cannot be satisfied by ZIP generation)
Verified publisher and appropriate organization role; public domain ownership/challenge; OAuth connection; tool scans and policy review; developer attestations; account availability; approval then deliberate publication. Do not publish, overwrite domain challenge files, create accounts or deploy without separate authorization.

## Updates
Preserve existing identity; maintain complete sources and bump explicit version. Upload complete package for metadata/skills changes. Hosted tool updates and rescans are separate; keep backwards compatibility until new definitions approved. Captured flow says MCP cannot simply be added to existing skills-only public listing and URL changes may require support: confirm before planning a migration. Do not create an inaccessible MCP to 'reserve' a future integration.

The local public validator covers only a subset of these requirements. Consult tool-coverage.md and report untested portal fields/auth/UI explicitly.
